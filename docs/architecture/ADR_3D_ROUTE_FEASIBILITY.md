# ADR：3D 路线可行性与产品边界

本文记录实时 3D 重建路线的工程评估与正式决策，避免把浏览器关键点预览、离线 FLAME/HeadSpace 资产处理和真正的实时个体化重建混为一谈。

- 状态：Accepted（#40 owner @ArXee 已正式确认）
- 提议日期：2026-07-29
- 接受日期：2026-08-05
- 决策 issue：[#40](https://github.com/jwj1342/LangerFace/issues/40)
- 已执行的入口收口：PR [#108](https://github.com/jwj1342/LangerFace/pull/108)、PR [#110](https://github.com/jwj1342/LangerFace/pull/110)

## 已接受决策

项目采用 **2D-first 实时路线 + 3D 离线预处理/研究查看路线**：

1. 不恢复面向用户的实时 3D 重建、FLAME 实时孪生或 3D 投影入口。
2. 照片、视频和摄像头叠加继续走 MediaPipe 关键点上的 2D 重心映射，并保留现有姿态、运动、局部质量和遮挡门控。
3. FLAME、HeadSpace、网页 3D 标注和 Three.js 仍可用于离线资产生产、图谱标注/复核和切口候选研究预览；这些能力不得被描述成患者个体化临床 AR 注册。
4. `web/src/services/mode3d.ts` 等没有用户入口的实时 3D 残留不是产品承诺。共享依赖与
   lifecycle 的拆分归现有技术债 epic #95；只有在 `/annotate`、`/incision` 和研究演示的
   消费边界拆清并有回归测试后，才可在 #95 的后续小 PR 中删除，不应为了保留历史路线而
   重新开放入口。

这项决策不删除确定性 workflow，也不影响 `/incision` 中保留的 3D 头模与候选可视化。

## 四项 Gate

| 维度 | 当前证据 | 实时路线通过门槛 | 当前工程评估 |
|---|---|---|---|
| 端到端耗时 | 引用 #40 已记录的团队历史基线：8 GB GPU 上 SfM 约 30–60 秒，CPU 更慢；这不是本 ADR 新做的 benchmark。浏览器“9 秒扫描”还不包含稠密重建或贴图 | 目标设备上中位数 ≤ 2 秒、P95 ≤ 5 秒，且包含采集、个体化几何、贴图和可投射资产生成 | 不通过 |
| 算力 | `tools/headspace/` 的完整研究管线依赖 Blender/`bpy`、`trimesh` 和多视图融合；FLAME 线性拟合虽可在 CPU 离线运行，但不等于实时稠密重建 | 默认部署无需 GPU、Blender 或常驻原生服务；若需要这些资源，必须先批准新的受控后端架构 | 不通过 |
| 部署承载 | 当前生产是 Vite 静态站点；Vercel 只托管构建产物，没有 GPU/Blender 运行时。PR #110 已删除不符合边界的 `/api/fit` 云函数 | 现有静态部署可承载，或另有完成鉴权、配额、体积限制、错误脱敏和成本评审的受控服务 | 不通过 |
| 质量差距 | `mode3d.ts` 将多帧 468 关键点刚性对齐后取逐点中位数，拓扑固定、没有稠密几何；真实重建还会叠加几何、贴图与投影误差。目前没有患者级误差上限或临床验证集 | 必须为几何、贴图、投影分别定义可复现误差预算，并在受控真实数据上证明组合误差满足预先登记的阈值 | 无法评估；误差预算与阈值尚未定义 |

前三项分别基于既有团队基线或当前仓库/部署架构事实评估为不通过；第四项因缺少预先定义的
误差预算和临床验证集而无法评估。#40 owner 已于 2026-08-05 正式接受这些边界；当前工程
继续保持不恢复实时产品入口。未来的重启 gate 不代表当前路线已经满足相应门槛。

这里的证据等级必须保持可追溯：耗时是引用 #40 的既有基线，算力与部署承载是对当前
依赖和静态部署边界的代码/架构核查，质量项则明确没有足够证据。本文没有把这些材料
表述为一次新的独立性能或临床评测。

## 三条容易混淆的路线

| 路线 | 实际能力 | 当前状态 |
|---|---|---|
| 实时 2D | 每帧把 atlas 重心坐标映射到当前 MediaPipe landmarks，随表情更新；深度和大角度自遮挡能力有限 | 当前主线 |
| 浏览器关键点 3D 预览 | 多帧刚性对齐后的 468 点中位数网格，可旋转和做工程预览；不是 SfM、稠密重建或临床级个体模型 | 用户入口已关闭；残留 runtime 待依赖拆分 |
| 离线 FLAME/HeadSpace | 在 HPC/本机生成或拟合网格、迁移图谱、渲染和人工复核，再把静态资产交给浏览器 | 允许的研究/资产路线 |

`/annotate` 的 3D 表面标注、`/incision` 的头模预览和 `/surgery` 的定性演示不属于“实时 3D 重建入口”，因此不因本 ADR 删除。

## WASM 依赖

MediaPipe WASM 是否自托管是实时 2D 路线的供应链与可用性问题，应独立处理。它不会改变本 ADR 对实时 3D 重建的工程评估。
