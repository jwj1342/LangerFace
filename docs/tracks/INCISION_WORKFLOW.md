# 本地确定性切口 workflow

本文记录 `/app/incision` 当前保留的切口候选 workflow。它完全在浏览器内运行，不包含远程模型、AI SDK、Provider 配置、自主规划或多轮推理。

该功能是临床研究决策辅助可视化，不是自动手术指令或已验证医疗器械。

## 当前产品验收范围（2026-08-17）

当前开发和阶段联合验收采用方案 B：只以单个、轮廓清楚、整体近似圆形（允许轻度椭圆）的皮表肿物验证受控识别与梭形生成，明显狭长椭圆不自动纳入。复杂不规则轮廓、明显缺口和人工补线的既有实现继续保留为兼容性能力，相关结果单独报告，不计入当前阶段通过率，也不承诺对任意形状稳定恢复。底层自由轮廓和补线契约仍按下文运行，避免破坏既有数据、测试与历史记录。

## 运行边界

- `web/src/services/incisionWorkflowTools.ts` 按固定顺序调用确定性工具，生成候选、工具 trace、门控结果和候选比较。
- `web/src/workers/workflow.worker.ts` 通过 Comlink 在 Web Worker 中执行同一套 workflow。
- `web/src/services/workflowPlanner.ts` 在 Worker 不可用时回退到主线程执行相同的确定性函数。
- `web/src/services/incisionRuntime.ts` 负责工作台编排、三维交互、导出和实时叠加衔接；route-scoped DOM 收集、临床展示文案和审阅门控分别由 `incisionDom.ts`、`incisionClinicalCopy.ts` 与 `incisionReviewPolicy.ts` 维护。
- 工作台固定使用 `mediapipe-468` 面部表面，不加载 FLAME basis，也不把 MediaPipe 图谱转换到 FLAME。
- `incisionAtlasSource.ts` 优先接收 `/personalized` 暂存的 YOLO/V6 个体化 RSTL；仅在缺失、来源不符或
  拓扑校验失败时使用内置标准 RSTL，并把降级原因写入 UI、snapshot 和审阅导出。

### 跨页面同源契约

实时页与切口页通过 `rstl-source-contract/v0.1` 报告当前图谱的 system、atlas/topology 版本、
provenance、`validated` 状态、线/点数量和确定性几何指纹。契约相同表示两条链路消费了同一份可追溯
surface 数据；故意更换图谱点、拓扑、版本或来源时，比较器会返回结构化 mismatch code。

“同源”不表示两个页面的最终像素必须完全相同。mirror、contain、pan、zoom、DPR、线密度和额头可见性
裁切属于显示阶段；它们可以产生可解释的像素差异，但不得静默改变 atlas、topology、provenance 或
surface refs。所有当前图谱仍保留 `validated:false`，同源回归只证明工程数据链一致，不构成医学验证。
### 受控标记定位 baseline

照片页的“受控标记”是保持式开关：开启后，用户可在模拟肿物曲线内部点击。v0.10 检测器按照片
尺寸建立多尺度有界 ROI；旧全局暗色连通域仍保留为兼容路径，失败时再使用局部相对暗色屏障、严格 closing、
方向受限的小缺口修补和 seed-first flood-fill。只有被原始暗线充分支持且不泄漏到 ROI 边缘的区域才能成功；
轮廓若与头发、皱纹或阴影相连，面积检查只计算真正围住点击区域的轮廓带，不再吸入整片相连暗区。
对于空心手绘标记，检测器返回
黑色笔画包围的内部区域及其面积中心，而不是把笔画本身的外沿当作病灶；原笔画面积和包围盒只保留为诊断。
种子点只负责选择目标，不应改变同一闭合标记的识别范围。结果经 `lesion-detection-adapter/v0.1` 校验后，
直接使用界面上已经填写的肿物类型和切缘生成候选，不再要求第二次点击“确认定位”。

识别失败时开关保持开启，用户可直接换位置重试；再次点击“退出标记”或退出照片模式才关闭该模式。
皮表受控标记边界独立于“椭圆近似/自由轮廓点”下拉框。该自由轮廓能力是保留的兼容契约，不等于当前阶段验收覆盖复杂形状。识别区域用于校正规划中心并记录面积、等面积圆直径、
外包类圆直径、紧致度和中心偏移诊断；候选尺度使用以识别中心为圆心、能够包住原始识别边界的类圆直径与
人工切缘，界面的人工肿物直径只保留为审计值。原始不规则边界不会直接扭曲标准梭形，但继续参与覆盖与异常门禁；复杂边界结果只作兼容性观察。
该自动尺度仍属于研究工程规则，不构成医生确认的真实病灶边界或已验证临床参数。
检测全程在浏览器本地 Worker 执行，不保留或导出原始像素；工程诊断仍在内部返回，但医生操作区只显示
“当前点击区域未识别到肿物”等浅显中文，不展示失败码、ROI 或阈值术语。

该 baseline 用于验证“受控目标 -> surface refs -> 切口候选”的工程链路，不能识别真实病灶的性质、
边界、深度或切缘，也不能把眉毛、鼻孔、头发等深色区域当作无需人工确认的病灶。

- 运行时不读取模型密钥，不请求远程模型，也不把原始照片、视频帧、摄像头画面或纹理发送到外部服务。

### 工程开口避让

候选完整路径会与 MediaPipe 468 拓扑中的双眼开口和口裂闭环做相交检查；相交时产生
`candidate_intersects_non_skin_opening` 硬阻断。该检查只防止候选线穿过明显的非皮肤开口，是工程完整性
门禁，不代表眼周、口周的医学安全距离，也不能替代医生对真实解剖结构、功能风险和切缘的判断。

通用流程另对 MediaPipe 外唇闭环应用保守的红缘保护：候选跨越时阻断，并提示使用专门口唇流程或记录
医生覆盖原因；该保护不禁止把病灶中心放在口唇，也不表示临床上不能进行有指征的口唇切口。

工作台把医生需要先看的候选摘要、保护规则和验证边界保持为默认可见；workflow trace、工具门控与候选比较收进默认折叠的技术详情。移动端先展示可定位病灶的三维视图，再进入长表单。

## 固定步骤

1. `summarize_tumor_input_quality` 检查肿物输入、单位、来源、作者、深度、切缘和边界；受控标记另生成
   `incision-lesion-normalization/v0.1` 诊断并确定面积中心，人工直径仍是规划尺度。
2. `classify_region` 在最终规划中心计算面部分区、亚单位和敏感游离缘距离。
3. `query_rstl_direction` 的切口侧适配器从现有 RSTL 图谱选择距离规划中心最近的单个线段，并以该线段切线
   作为候选方向；等距冲突会降低置信度。该适配器只读消费既有图谱，不修改共享 RSTL 生成、个性化、密度、
   `mapAtlas()` 映射或实时页显示规则；标准 RSTL 仍只作为显式降级。
4. `inspect_sensitive_structures` 检查敏感结构和保护性方向例外。
5. `linear_subcutaneous_incision` 或 `fusiform_cutaneous_incision` 生成主候选。
6. 对候选复查敏感距离并运行 `evaluate_guardrails`。
7. `preview_incision_on_face` 验证几何可在标准脸上预览。
8. 生成 `-10° / 0° / +10°` 三个固定方向备选，并分别复跑候选生成、敏感结构检查、guardrails 和预览。
9. `compare_candidates` 按工程指标排序，供医生审阅。

## 输出契约

- `candidate_alternatives`：方向备选及各自的几何、guardrails、敏感结构检查和预览。
- `candidate_comparison`：工程排序，不是临床推荐。
- `workflow_trace_gate`：检查固定关键步骤是否执行且顺序正确。
- `workflow_plan_audit`：从 trace 派生的步骤审计。
- `workflow_execution_events`：用于 UI 和导出的本地执行事件。
- `workflow_audit`：候选数、预览数、比较状态、失败重试与恢复摘要。
- `summary` 与 `next_step`：由本地规则生成的固定说明文本。

机器可读契约见 [`assets/incision_workflow_schema.json`](../../assets/incision_workflow_schema.json)。

原始 YOLO mask 或单独导入的皱纹 / 病灶 metrics 不直接参与上述方向查询。进入几何的个体化 RSTL 已经
过 V6 的 prior 约束、方向一致性、最大位移、皮肤域、禁区与拓扑校验；它仍是研究草案，不能替代医生审阅。

审阅记录与导出容器从 Agentic 字段迁移后分别使用 `incision-review-record/v0.4` 和
`incision-review-export/v0.4`；React controller snapshot 因移除 provider 状态并把 `agent_*` UI 字段改为
`workflow_*`，升级为 `react-incision-controller-snapshot/v0.2`。`tools/evaluate_stage2_validation.py`
仍兼容读取旧 `v0.3` 审阅导出，并在 summary 中分开报告源 schema，避免旧新结构静默混读。

旧书签 `/incision_agent.html` 只保留一个无运行时代码的跳转页，统一重定向到 `/app/incision`；
它不会恢复 Agentic 模式、Provider UI 或远程模型调用。

## 医生审阅

候选可编辑、确认、退回或否决；每次编辑都会重算几何和 guardrails，并记录 provenance。医生通过单一状态选择器选择“待确认 / 确认 / 退回 / 否决”，再用“保存所选审阅状态”写入候选库，避免状态选择器和确认/否决按钮重复表达同一决策。工具门控未通过、缺少审阅人或高风险提示缺少说明时，候选不能标记为可发送到实时叠加。

医生调整历史保存完整快照。滑杆参数提交后再补充调整理由时，系统把同一组参数与理由合并为一个事务，
并以交互来源和完整参数写入 provenance；提交时间只留在当前标签页的内存历史中，不进入导出，避免触发隐私门禁。
预览仍可即时刷新，但不会因此产生第二条临床编辑记录。
“恢复工具建议”会同时恢复参数、预览与编辑历史基线。理由只记录说明，不自动套用任何未确认的医学参数预设。

### 3:1 分母观察与待决策项

当前工程实现计算手工自由轮廓的皮表梭形候选时，先取病灶直径与自由边界垂直径中的较大值，再加双侧切缘形成
候选宽度，并以该候选宽度作为 3:1 的分母。受控标记候选不再由原始笔画轮廓扩张，而按人工直径与双侧切缘
生成标准候选。机器可读 metrics 显式记录：

- `length_ratio_basis_mm`：本次实际使用的工程分母数值；
- `length_ratio_basis=lesion_perp_diameter_plus_bilateral_margin`：分母口径；
- `clinical_ratio_basis_status=requires_clinician_confirmation`：临床口径尚待医生确认。

| 待医生确认的问题 | 当前工程行为 | 本轮处理 |
|---|---|---|
| 3:1 是否应以病灶直径而不是含切缘宽度为分母 | 使用“病灶/边界垂直径 + 双侧切缘” | 只增加观察字段，不改公式 |
| 自由边界较病灶直径更宽时采用哪个直径 | 采用二者较大值 | 保持现状，等待临床决定 |
| 修改分母后最小/最大长度限制如何协调 | 仍按现有规则 clamp | 不推断新阈值 |

这组字段用于对照测试和医生决策，不表示当前分母已经获得临床确认。

“生成候选切口”的计数只记录医生明确点击生成按钮的次数。点击面部重选病灶或修改直径、深度、切缘等参数仍会自动刷新候选预览，但不再冒充一次明确生成。

## 实时叠加交接

确认候选后点击“进入实时叠加”，工作台会把经过审阅门控的 MediaPipe 表面引用写入当前标签页的 `sessionStorage`，随后直接进入 `/live?incisionOverlay=staged`。实时页会显示独立的“切口候选叠加”状态卡；上传照片、视频或开启摄像头后，候选使用与照片规划相同的共享显示 token，线宽不超过标准 RSTL 线宽的一半，并以细深色 halo 保持对比度。线性候选为绿色，梭形候选为青色；病灶中心和边界使用黄色标记。用户可在实时页明确清除候选，不影响 RSTL 图谱。

照片规划与实时视频/摄像头都从 `incisionOverlayStyle.ts` 读取候选类型、颜色、线宽和 halo token；视频和摄像头继续共用 `render2d.ts` 的同一叠加函数。实时源仍受姿态、快速运动、张口和眨眼质量门控；被门控的帧会在“切口叠加 QA”中显示原因，而不是静默表现为按钮无效。

该闭环是研究可视化工程实现，不等于临床功能完成：切口页使用 MediaPipe 468 标准规划表面，不是患者个体三维重建；病灶位置和边界仍由医生输入；规则资产仍处于未临床验证状态；尚未完成前瞻性临床验证、真实深度/组织力学建模或监管验证。

### 未来单页合并约束（规划，未授权实施）

当后续提出“页面合并”“功能合并”或“页面简化”时，应先展示并复核本节规划，不得直接改写界面或数据流：

1. 删除个性化采集的入口、页面和可操作控件前，先盘点其对图谱资产、运行时数据和历史路由的依赖；目标是移除用户可见的个性化采集流程，不是未经核账直接删除共享资产或底层文件。
2. 合并页只保留一个共享人脸画布，中间可切换照片、视频和实时摄像头。左侧承载现有实时 2D RSTL 操作，右侧承载现有切口候选研究操作；初版只允许调整布局，不修改两侧既有按钮、操作语义、输入输出、视觉规则和模块责任边界。
3. RSTL 与肿物边界/候选切口必须使用同一媒体帧、同一组当前人脸 landmarks 和同一画布合成链，可同时显示、分别门控和独立清除；任一侧操作不得覆盖或重置另一侧结果。
4. 切口规划完成后不再通过页面跳转进入实时叠加。经现有审阅门控的候选在照片、视频和摄像头切换间保持同一表面引用；二维屏幕形状应随头部姿态、透视、遮挡和可见区域自然投影，不能把“形状不变”实现为屏幕坐标固定。不可见部分应隐藏，重新可见后应恢复到同一面部位置。
5. 合并验收至少包括：不存在个性化采集入口；媒体切换不丢失已审阅候选；左右模块既有交互契约不变；两类叠加可同时显示且互不干扰；没有新增医学结论、患者数据上传或持久化行为。

在合并获得明确授权前，当前 `/app/incision` 到 `/live?incisionOverlay=staged` 的交接链继续作为现行实现，不得为了未来规划提前拆除或放宽门禁。
